## KRİTİK

- [x] K1. **DB proxy — dizi (array) gövdesiyle alan temizliği atlanıyor** (KOD) — `backend/src/routes/dbRoutes.js`
  `orders` POST'ta `delete body.amount / status / paid_at` sadece nesne gövdede çalışıyor.
  `body: [{ amount: 1, status: 'paid', ... }]` gönderilirse hiçbir alan silinmiyor ve
  `.insert(array)` ile anonim biri bile "ödenmiş" sipariş oluşturabiliyor.
  Düzeltme: gövde dizi ise reddet (veya her elemanı temizle); `status`'u sunucuda zorla `pending`.

- [x] K2. **Giriş yapmış kullanıcı siparişi `status: 'paid'` ile açabiliyor** (KOD) — `dbRoutes.js`
  `if (!user && body.status ...)` kontrolü sadece anonimi kapsıyor. Oturumlu kullanıcı doğrudan
  `status: 'paid'` gönderebiliyor.
  Düzeltme: herkes için `body.status = 'pending'` zorla.

- [x] K3. **`updateOrderConfig` sipariş durumunu istemciden alıyor** (KOD) — `backend/src/controllers/paymentController.js`
  `status: req.body.status || order.status` → sipariş sahibi `/api/templates/order-config`'e
  `status: 'paid'` yollayarak ödemesiz siparişi ödenmiş gösterebiliyor.
  Düzeltme: `status` alanını güncellemeden çıkar.

- [x] K4. **PostgREST ilişki-gömme (embedding) ile tablo sızıntısı** (CANLI) — `dbRoutes.js`
  `select` parametresi filtrelenmiyor. Anonim `templates` sorgusunda
  `select: "id,orders(*)"` ile `orders` tablosu (e-posta, ad, telefon, adres, tutar) okunabiliyor.
  Canlı kanıt: anonim `select:"id,orders(count)"` isteği 200 döndü ve her şablon için gömülü
  `orders` sayımı geldi (ilişki çözümlendi; satır verisi bilinçli olarak çekilmedi).
  Düzeltme: `select` içinde `(` karakterini / ilişki sözdizimini reddet; admin dışı için
  tablo başına beyaz liste kolonlar.

## YÜKSEK

- [x] Y1. **`auth-send-email` Edge Function kimlik doğrulamasız** — `supabase/functions/auth-send-email/index.ts`
  Supabase Auth hook'u ama `verify_jwt=false` ve webhook imzası kontrol edilmiyor. Herkes
  `{user:{email:"kurban"}, email_data:{...}}` POST'layarak hello@erpolart.com'dan resmi görünümlü
  şifre sıfırlama / doğrulama maili gönderebiliyor (spam, itibar, Resend kotası).
  Düzeltme: `SEND_EMAIL_HOOK_SECRET` ile standardwebhooks imza doğrulaması.

- [x] Y2. **`send-proposal-email` — `user_metadata.role` ile admin kontrolü** — `supabase/functions/send-proposal-email/index.ts`
  `user_metadata` kullanıcı tarafından yazılabilir (`auth.updateUser({data:{role:'admin'}})`).
  Herhangi bir kayıtlı kullanıcı marka adıyla, istediği linki içeren e-posta yollayabiliyor
  (phishing). `toName`, `projectName` HTML kaçışsız.
  Düzeltme: sadece `email === ADMIN` veya `app_metadata.role`; HTML escape.

- [x] Y3. **`create-pricing-order` — kimliksiz, tutar istemciden, e-posta relay** — `supabase/functions/create-pricing-order/index.ts`
  Bilinmeyen `source/tier` ile `MIN_PRICES` atlanıyor (1$'lık sipariş); `user_id` gövdeden geliyor
  (başkasının hesabına sipariş); `email` alanına sınırsız, HTML kaçışsız (`full_name`,
  `company`) mail gönderiliyor. Frontend bu fonksiyonu artık kullanmıyor.
  Düzeltme: fonksiyonu kaldır/devre dışı bırak; kalacaksa `computeServiceTotal` mantığı + JWT zorunlu.

- [x] Y4. **İletişim formu e-posta relay + HTML enjeksiyonu** — `backend/src/controllers/messageController.js`,
  `backend/src/templates/notifyEmails.js`
  `/api/messages` herhangi bir `email`'e otomatik yanıt yolluyor; `name` kaçışsız HTML olarak
  gömülüyor → marka domaininden phishing içerikli mail. Admin maili de `name/service` kaçışsız.
  Düzeltme: tüm kullanıcı alanlarını `escapeHtml`; e-posta format doğrulaması; uzunluk sınırı.

- [x] Y5. **Chat mesajı sahteciliği / başkasının oturumuna yazma** (KOD + kısmi CANLI) — `dbRoutes.js`, `backend/src/controllers/aiController.js`
  Kodda `user_` kontrolü yalnızca `if (user && ...)` dalında; anonim istek kontrolsüz geçiyor.
  Canlı kanıt sınırlı: var olmayan `user_0000…` oturumu için anonim GET 403 yerine
  `200 {data:[]}` döndü — yani yetki kontrolü atlanıyor; gerçek bir kullanıcının mesajı okunmadı.
  Yazma tarafı (POST) prod'da denenmedi. `/api/ai/chat`'te `userId` doğrulanmıyor.
  Zincir: `role:'assistant'` + `[tıkla](javascript:...)` → ChatBot link render'ında stored XSS.
  Düzeltme: `user_` ön ekli oturumlar için JWT zorunlu; `role` alanını istemciden kabul etme;
  ChatBot'ta sadece `http(s)` ve `/` ile başlayan linkleri render et.

- [x] Y6. **Bağımlılık açıkları** — `package.json`, `backend/package.json`
  Frontend: 8 high (axios, react-router 7.13 → RCE/DoS CVE, socket.io-client, ws, follow-redirects, form-data).
  Backend: 1 critical (proxy-addr IP spoofing → rate-limit bypass), 7 high (body-parser DoS,
  engine.io, ws, nodemailer, ip-address), 1 moderate (qs). Hepsinin düzeltmesi mevcut.
  Düzeltme: `npm audit fix` + `react-router-dom`, `express`, `socket.io` güncelle.
